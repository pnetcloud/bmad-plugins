# Docusaurus Standards

## Purpose and selection

Use for Docusaurus-specific content, docs plugin configuration, metadata, sidebars, versioning, and build decisions; not generic Markdown or non-Docusaurus sites.

## Working mode

Inspect the Docusaurus version, project configuration, active plugin instances, and existing build commands. Ask for missing site/instance or release target when it changes the work.

- Read each docs plugin instance from the project configuration; preserve its
  configured content path and explicit, autogenerated, generated, or disabled
  sidebar state instead of assuming `docs/` and one sidebar file.

## Focus

- Organize docs into clear sections and, when enabled, a coherent sidebar.

- Write in Markdown/MDX; keep docs concise and structured.
- Apply SEO tags and metadata for each page.
- Version documentation for major releases.

## Quality checks

Use the existing project build/link checks and record exact scope and result, including checks not run. A passing build is not evidence of deployment.

- Deploy docs via CI/CD pipeline; validate links and build.

## Return

Return the requested docs/configuration patch or review with affected instance, build/link evidence, and remaining version or deployment decisions.

## Boundaries

CI/CD guidance does not authorize deployment, publishing a documentation version, changing hosting, or installing/upgrading dependencies. Preserve configured paths and sidebar authority.
